# Conventions and evidence

Part of the [drover spec](README.md). All of this is new or changed.

## Commit style and text

- **FR-CNV-1** At onboard, the system shall classify the base branch's last
  50 commit subjects as conventional, plain imperative, bracket-tag, or
  other, and store the result as `commit_style` (`conventional`, `plain`,
  `bracket-tag`, `other`). Fewer than 10 commits or
  no clear majority defaults to conventional.
- **FR-CNV-2** Workers shall write commit subjects and PR titles in
  `commit_style`, given 3 real subjects from the repo as examples.
  (Upstream: `<emoji> [<type>] <scope>: <subject>`, enforced by
  `tests/test_writing_format.py`.)
- **FR-CNV-3** Text drover itself writes (comments, block notes, logs,
  status output, PR body sections, and the skills' chat output to the owner
  such as the onboard wizard and run progress lines) shall contain no emoji.
  GitHub alert boxes (`[!NOTE]`, `[!WARNING]`, `[!TIP]`) stay. The visual
  skill's HTML template is page design and keeps its glyphs. Run manifest
  lines keep their format apart from the approved emoji removal
  (metrics.md FR-MET-2).
- **FR-CNV-4** Every machine-read marker (thread prefixes, report marker,
  reason tags, gate output lines) shall be defined once, in a file used by
  both its writer and its parser. Upstream spreads these across
  `writing-standard.md`, `block-template.md`, `status.md` and scripts that
  grep for emoji. Reason tags live in `lib/drover-reasons.json`; thread
  prefixes, the review report marker and its lists, and the gate output
  prefixes (`human-gate:`, `needs-you:`, `approval-request:`) live in
  `lib/drover-markers.json`.
- **FR-CNV-5** drover shall add no attribution or "generated by" footer to
  commits or PRs.
- **FR-CNV-6** A builder shall mark a finished card with a commit-body
  trailer `Drover: done #<n>`, and partial work with `Drover: partial #<n>`.
  Scripts shall detect done and partial work from the trailer only, never
  from the commit subject. (Upstream: subjects `🔧 [chore] loop: close #N`
  and `🚧 [wip] loop: #N partial`.)
- **FR-CNV-7** Where drover names the person who must act (`Next:`,
  `Owner:`, the status alert), it shall write `owner`. (Upstream: `Eric`.)

## Evidence

- **FR-EVD-1** `drover onboard` shall ask where QA evidence goes and store
  it as `evidence`:
  - `{"mode": "branch", "branch": "<name>"}` (default, branch
    `drover-evidence`): an orphan branch, files under
    `runs/issue-<n>/v<k>/`;
  - `{"mode": "pr", "path": "<dir>"}`: the PR branch, under
    `<dir>/issue-<n>/v<k>/` (upstream behaviour, default dir
    `docs/drover/runs`). Evidence then reaches the base branch on merge.
- **FR-EVD-2** Comments shall embed evidence with raw URLs pinned to the
  commit SHA that added it, never a branch name.
- **FR-EVD-3** In `branch` mode, the PR branch and base branch shall contain
  no evidence files.
- **FR-EVD-4** Images over 5 MB shall be downscaled to at most 1920 px wide
  before commit. (Preserved rule, new location.)
